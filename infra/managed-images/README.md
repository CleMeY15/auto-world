# Managed-image correction diagnostics

These inputs implement the construction/audit subset of the [reviewed correction plan](../../roadmap/plans/TASK-0005-managed-image-corrections.md). They do not admit images, start support or complete TASK-0005.

The workflow `data-foundation-managed.yml` uses a disposable Linux runner with contents-read permission. It authenticates the official scanner, checks its binary/materials, self-audit and fixtures, then audits both pinned builder images before compilation. Only eligible builders proceed to the three standard Buildx recipes. Redis and SeaweedFS retain the exact upstream subjects already selected; all five runtime/helper roles still receive complete fresh reports and SBOMs.

The [reviewed Rust increment](../../docs/validation/TASK-0005-seaweed-rust-source.md) separately audits the exact SeaweedFS Cargo lock universes with the same scanner/database. Isolated locks preserve all498/590 packages; each JSON/CycloneDX inventory must match independently measured source pins. Two additional upstream Cargo controls require known vulnerable detection and a clean current-database result, without changing the frozen Go/Java fixtures. Stopped-container Docker copies and host Node compare both helper files to independently measured artifact hashes, without running candidate programs. Source-lock inventory and artifact-byte identity do not establish intrinsic binary crate inventory, source equivalence or signer trust. Eleven production context files plus two control inputs form the thirteen pinned source files.

Buildx loads a locally tagged image and emits metadata. Docker inspection must confirm its Linux/amd64 configID. A standard Docker-save archive is hashed before/after scanning with `trivy image --input`; that configID/archive identity is explicitly not an authenticated registry subject. Reports retain their original names and contents. All CRITICAL and fixable HIGH findings block, unfixed HIGH needs its existing exact disposition, and the vulnerability DB remains at most 48 hours old.

The measured source-built gosu main deliberately has no published Go-module version. Its narrow reviewed profile binds the complete measured Go inventory and binary bytes, checks the final binary in its exact configID, and preserves the original report/SBOM. Only after that binding, the versioned-package policy receives a detached view without the sole source-bound main. Any main finding blocks, all other findings remain unchanged, and the receipt retains the full raw/versioned/source-bound counts plus `mainVersionLookup=UNAVAILABLE`. A positive diagnostic cannot claim exhaustive vulnerability absence for gosu; source/advisory review remains required before final admission.

Each Dockerfile has a deny-all context allowlist. Private workspace data, `.omx`, `.local-data`, host Git state and credentials are excluded. Build commands use a reduced environment and no publication/signing capability. Only validated bounded UTF-8 technical text/XML/JSON from the evidence target is copied to the public-artifact directory. Raw image archives, compiler binaries, database binaries and unvalidated exports are excluded.

After all five same-job image audits, three builds/exports, both Rust controls, both source-lock audits and both helper identities pass, the managed adapter prepares the two unchanged upstream runtime images by audited platform digest and compares all five actual configIDs to the original reports. Original five-role reports are collected before Rust work; their named aggregate rejection is deferred only for further diagnostic collection and still blocks runtime. It invokes `tests/managed-image-runtime.integration.mjs` outside the pure-test globs. Four ordered cases cover startup/UIDs and S3 authentication refusals; SQL/raw/index/search; restart without rewriting; and cold canonical restoration with the index reconstructed from target SQL. Two fresh owned UUID projects use bounded commands and scoped cleanup. Private inputs, credentials, archives and child logs stay outside public artifacts; only the exact validated run/configID bindings, four finite case outcomes and cleanup result may be published.

`functionalRuntime` becomes `VERIFIED_DIAGNOSTIC_ONLY` only after all four cases pass, the child exits successfully and cleanup is verified. Missing/failed cases or uncertain termination prevent success. `milestone2Completion=NOT_ESTABLISHED` and `admission=NOT_AUTHORIZED` remain explicit pending independent acceptance. Earlier build/audit-only receipts retain `PENDING_NOT_ACCEPTED`; later code never supplies them retroactive runtime evidence. The [M2 delivery boundary](../../roadmap/plans/TASK-0005-managed-m2-delivery.md) still requires actual result review and protected head/main checks. Exact registry-subject validation, complete private retention/restore, authenticated admission and all seventeen phases on the final admitted subjects remain separate gates. The three final-JDK text reads alone remain inventory evidence.

Targets are `runtime` and `evidence`, with the repository root as context. PostgreSQL's final target imports only the tested gosu binary and notices into its original base. AWS performs a complete signature-checked transaction against the exact dated AL2023 repository and proves its CLI installation unchanged. OpenSearch builds the upstream minimal no-JDK core, retains all source/dependency tests and license checks, and preserves its base's JDK separately from the compiler JDK. Captured failed Gradle statuses can be exported; they cannot produce an accepted runtime target.

The combined job requires 20 GiB free runner disk before preparation and has a 240-minute deadline; individual builds have 90-minute limits. The scanner retains its existing container CPU/memory/PID/read-only/network restrictions. No global Docker pruning, host installation or cleanup of historical resources is introduced. Runner retention is disposable, never the required supported archive or second private copy.

Windows checks are limited to pure contracts and file-validation fixtures. Linux-only shell, filesystem, ownership and race checks must run on Linux; their exclusions on Windows do not establish native success. Actual DNF, Go/Gradle compilation, upstream tests, candidate audits and the four runtime cases need their own reviewed CI evidence. The original upstream subjects remain rejected by unchanged policy; historical-image integration does not validate the derivatives. Dated observations and exact source/run identities are recorded in [the validation record](../../docs/validation/TASK-0005-managed-tools.md).

Rollback abandons only these unadmitted diagnostic inputs and preserves all data volumes, backups, source/evidence archives and historical support duties. Publication, retained restoration, authentic admission and activation require their existing separate gates.
