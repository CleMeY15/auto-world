## Verified filesystem boundary addendum

The source assumes the existing reviewed private lease and a trusted host/kernel/UID1000 actor with quiescent archive writers. It does not defend against a malicious same-UID process or privileged host that can alter content/namespace and disguise changes. O_NOFOLLOW protects the final component only; Node22 path-based openSync has no documented openat/dirfd-relative child-open API. Held parent FDs, canonical realpaths and repeated held/named guards detect observed identity changes but are not an atomic whole-path confinement guarantee. Any observed intermediate symlink or replacement fails closed; no claim of undetectable-race prevention or OS immutability is made. The later authenticated controller must establish exclusive source ownership/quiescence and revalidate hashes/snapshots after daemon stop before granting preservation.

O_RDWR descriptors are used without writing; fsync flushes existing data/metadata and does not itself create a content snapshot. O_NONBLOCK is a liveness measure, not a type check: an O_RDWR FIFO may open on Linux and must be rejected by fstat before any read or seal. Directory and file guards surround every synchronous fsync/close, but cannot interrupt a blocked synchronous syscall. The later native controller must supply the separate bounded process/owned-stop supervision; these source tests establish fail-closed decisions after observations, not preemptible I/O, crash/power-loss durability or guarantees across filesystems/devices. Never retry a failed close on Linux: the descriptor may already have been released and reused.
