The optional expected `imageId`, when supplied, must match raw `Id`. Relevant raw arrays/maps are checked directly so an adapter cannot hide an extra tag, label, volume, command, entrypoint, port, healthcheck or filesystem DiffID by omitting it from a projection.

`validateSeaweedGoS3QualificationContainer` likewise receives the raw one-record JSON array from `docker container inspect`. It validates raw identity, name, image, Config, State, HostConfig, NetworkSettings and Mounts before deriving normalized evidence. It proves exact name/image, state `created`, never running/started, no network endpoint, security/resource settings, no bind/tmpfs/device and exactly one anonymous `/data` volume. Root must reuse these raw validators when it records known IDs/volume names and before it deletes an attempted object as owned. Unknown or additional security-relevant raw values refuse; Moby bookkeeping fields outside the qualification contract may exist but cannot replace or weaken any validated raw property.

## Monotone ownership journal

The lifecycle alone owns a monotone journal. Each path, image tag or container name is appended before its first create/import/copy attempt. Entries are never removed, retried or reclassified as foreign.

```json
{
  "schemaVersion": 1,
  "owner": "canonical UUID",
  "labels": {
    "control": "inert-v1",
    "owner": "canonical UUID"
  },
  "paths": [
    {"stage":"fixture|source-export|filtered-rootfs|final-save|roundtrip-export","path":"absolute","attempted":true,"snapshot":null}
  ],
  "images": [
    {"stage":"source|filtered","tag":"exact tag","attempted":true,"imageId":null}
  ],
  "containers": [
    {"stage":"source|filtered","name":"exact full-UUID name","attempted":true,"containerId":null,"volumeNames":[]}
  ]
}
```

Known snapshots, IDs and positively inspected anonymous volume names may move only from `null`/empty to their exact observed values. Ambiguous import/create output remains attempted and forces cleanup by exact tag/name plus owner labels. It can never pass or generate finite refusal evidence. Cleanup removes containers with their volumes, then exact owned images and files. It never enumerates into wildcard deletion and never touches foreign objects.

## Closed ordering

1. Validate source receipt/input and check elapsed time.
2. `assertInputsUnchanged`; validate tools inherited from source receipt; recheck resource identities/free space.
3. Derive names and require all names/files absent.
4. Journal fixture path; write fixture; validate exact process/report; lock/capture/inspect it.
5. Journal source tag; import fixture; inspect/bind exact image.
6. Journal source container; create and inspect exact stopped/never-started/security/volume state.
7. Strict diff before; journal/export; strict diff after; lock/capture; compare exact 16-member semantics and sentinel.
8. Journal filtered path; copy once; prove original unchanged; invoke GNU delete once; lock/capture; compare exact two removals and raw survivors.
9. Journal filtered tag; import filtered rootfs; inspect/bind exact final image/config/labels.
10. Journal final-save path; bounded save; lock/capture; inspect strict classic legacy single-layer save.
11. Journal filtered roundtrip container; create/inspect; strict diff before; journal/export; strict diff after; lock/capture; compare exact 14-member semantics and sentinel.
12. Recheck all immutable inputs, locked files, resource identities/free space and elapsed time.
13. In `finally`, invoke `cleanupOwned(journal)` exactly once and require `cleanupAbsent(journal)` to return all four booleans true.

The first failure stops all later qualification operations except cleanup. No construction/runtime callback exists.

## Independent review corrections

Before final validation, independent review found inconsistent UUID syntax, insufficient raw-container configuration/network checks, report commitment links and refusal-operation typing. These are corrected against the published contract with negative tests. The adapter reserves ten of the existing thirty minutes for cleanup and limits normal provider execution to twenty minutes; every cleanup command uses the remaining total deadline. No timeout exception or permission expansion is introduced.

The reviewer also reproduced a hidden GNU long-name header accepted behind tarfile's projected metadata. Qualification now keeps the original conservative single512-byte-header rule for every member and refuses all extended metadata regions, including PAX and GNU. Its fixed short paths, link target and integer timestamps require no extensions. This follows the parent instruction to refuse if offsets cannot establish closure rather than adding a custom parser; source recognition remains unchanged. The new qualification does not claim PAX fidelity. Python's closed legacy inspector requires server version exactly28.0.4. Fresh tests and actual Linux evidence remain required.
