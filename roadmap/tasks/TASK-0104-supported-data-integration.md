## Goal and dependencies

Implement the accepted SDK's fenced transactional `StorePort` on real PostgreSQL in the isolated synthetic V1 composition, preserving public contracts. Depends on ADR-0028, TASK-0005's accepted PR222 functional milestone and TASK-0101/0102 contract tests on `main`, not on deferred image admission. This task does **not** build an index, replace the API read port or activate a real source; those are separate tasks. The first implementation step is to freeze the focused storage ADR, schema/migration and dev/test entrypoint design before coupling consumers; no storage contract is invented by the dependency amendment.

## Relevant contracts and scope

[P1 plan](../plans/TASK-0006-synthetic-first-slice.md), [ADR-0007](../../docs/decisions/ADR-0007-private-image-admission.md), [ADR-0012](../../docs/decisions/ADR-0012-synthetic-development-lane.md), [architecture](../../docs/architecture/ARCHITECTURE.md), [SDK API](../../docs/decisions/ADR-0003-connector-sdk-api.md), [data platform](../../docs/data/DATA_PLATFORM.md), [security](../../docs/security/SECURITY_LEGAL.md), [DoD](../../docs/DEFINITION_OF_DONE.md). Object-store archival is out of scope; a future archive would have to consume committed outbox events asynchronously and never substitute for PostgreSQL transactionality. No fixture state is migrated automatically into production.

## Acceptance and test strategy

- Versioned backwards-compatible schema and migration apply/reapply/rollback pass without rewriting historical observations. Raw bytes/digest, checkpoint and ledger/outbox stage atomically under a fence; source-scoped full/explicit deletion preserves historical evidence. Exact replay/idempotency and retention expiry obey the SDK port contract.
- Use the exact pinned PostgreSQL identity of the accepted functional stack in a separate prototype entrypoint; preserve the supported admission broker unchanged and never fabricate admission evidence. Image changes require fresh affected functional evidence, not a new prerequisite to finish the deferred qualification. Crash/partition, stale-fence, lost-acknowledgement and isolated backup/restore tests prove raw SHA and ledger consistency on real PostgreSQL. S3 archival and OpenSearch are not part of this task's completion claim.
- Sanitized mutation events and migration/rollback runbook are recorded; failures stop the consumer without deleting data. Targeted migration/transaction/recovery tests, ordinary root quality/secrets/dependency gates, exact-head/merged-main CI and independent architecture/security/privacy/data/SRE review of changed application boundaries pass; evidence in `docs/validation/TASK-0104.md`. The review excludes deferred TASK-0005 image/scanner/admission qualification. Record completion as `DONE_FOR_V1_PROTOTYPE`, with that qualification still deferred rather than passed.
- The only permitted input is a synthetic fixture through the explicitly isolated dev/test composition, unavailable from production imports or user-controlled mode selection. Preserve loopback, resource/credential/ownership limits and existing raw/provenance contracts. No real-source activation, OpenSearch success, service-wide recovery or production readiness is claimed by this task. The complete image/security/admission gates remain prerequisites for later supported or exposed operation, not for this prototype implementation.
