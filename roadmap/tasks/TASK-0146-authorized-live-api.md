# TASK-0146 — Contrôle live d'un flux automobile documenté

24 novembre 2026 — suite à TASK-0145 et à l'accord utilisateur pour obtenir un flux de 500 annonces réelles accessible par une interface autorisée.

## Source et périmètre
- PistonTraders, UK : https://www.pistontraders.co.uk/developers/vehicles-api/ ; schéma https://www.pistontraders.co.uk/developers/vehicles-api/schema/ ; guide https://www.pistontraders.co.uk/developers/vehicles-api/llm-guide/.
- Les pages de documentation indiquent une API publique JSON en lecture seule, prévue pour les développeurs et agents IA, sans clé, et demandent de préférer cette API au scraping des pages. La spécification OpenAPI mentionne néanmoins BearerAuth ; le résultat HTTP réel prime, tout refus arrête l'essai.
- GET uniquement https://www.pistontraders.co.uk/api/v1/vehicles/?page=N via pagination documentée. Aucun accès aux pages des concessionnaires, aucune relance Jina/Leboncoin, pas de changement d'identité ni contournement. Une campagne, 25 appels maximum, 3 secondes minimum entre débuts des requêtes, 500 résultats maximum traités, délai de 5 min. Stop sur erreur HTTP, redirection, timeout, réponse non JSON, challenge, pagination incohérente ou répétition intégrale de page. Aucune relance d'un refus.
- Vérifier les champs natifs make, model, price (GBP), year, mileage (miles), car.url et champs supplémentaires documentés. Le lien canonique est la clé de dédoublonnage dans l'échantillon (hash en mémoire), pas une preuve de VIN distinct. Ne pas inventer les valeurs nulles, ne pas suivre les liens, ne pas enregistrer descriptions, contacts, photos, liens individuels ou contenu brut.
- Vérifier la fidélité du parseur existant sur des cartes Markdown reconstituées avec les valeurs **live** valides, prix GBP->EUR facteur fixe de test 1,15 et miles->km 1,609344, IDs techniques artificiels pour le parseur. Ce replay est distinct de la lecture native Jina ; il ne démontre pas l'accès Jina au site.
- Rapport JSON : tentatives avant envoi, réponses HTTP, durée, annonces reçues et traitées, validité par champ, valeurs nulles, duplicates, erreurs par page/numéro sans contenu brut, motifs d'arrêt, qualité du replay, limites et non-aboutissement. Conserver preuve agrégée même en échec.
- Les données restent en mémoire, aucun import base PostgreSQL, aucune republication, aucun droit contractuel de collecte industrielle déduit de la documentation de recherche. PR brouillon, workflow one-shot. Tests unitaires hors réseau avant accès.
- Critères distincts : 500 résultats réellement reçus/traités, nombre d'URLs uniques, nombre de fiches complètes, exactitude du replay sur les fiches éligibles. Ne pas compléter les manquants par fixtures. L'essai ne valide pas une acquisition Leboncoin/Jina ni l'usage commercial.
