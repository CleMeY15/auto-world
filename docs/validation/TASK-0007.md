## Framework and dependency decision

- Reuse the ROADMAP's Next.js/React/TypeScript reference stack, not a custom app shell or second UI framework. Next.js **16.3.8**, React/React DOM and their types **19.3.0** are exact lockfile pins. Node **22.23.2**, pnpm **10.15.0** and TypeScript **5.9.2** stay aligned with the existing workspace. Selection was independently checked against [Next releases](https://github.com/vercel/next.js/releases), [support policy](https://nextjs.org/support-policy), [installation](https://nextjs.org/docs/app/getting-started/installation) and [React's release](https://react.dev/blog/2026/09/09/react-19-3), rather than adopting an unreviewed new minor.
- Runtime dependencies: Next, React/DOM and the workspace design system only. The design package has a React peer, no runtime data/service dependency. Next/React/types are MIT; dev-only Playwright is Apache-2.0 and its axe wrapper MPL-2.0. Playwright **1.64.0**, axe wrapper **4.13.0** and React Hooks plugin **7.1.1** are pinned. ESLint's existing core/TypeScript rules and React Hooks recommended rules remain; no competing full ESLint preset.
- The initially selected optional Next ESLint plugin introduced the only audit finding: **HIGH** unpatched `braces` through `fast-glob`/`micromatch`, [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Independent upstream/dependency review confirmed that stable, maintenance and canary plugin releases still resolve the affected dependency and there is no compatible patched pin. Remove that optional development plugin, not the Next runtime; no audit exception, threshold change, custom fork or new replacement dependency. Scope-specific build/import/markup/browser checks remain, and there are no remote scripts/fonts/images, Pages Router or async client components. Reconsider the matching plugin only after its published dependency graph passes `pnpm audit --audit-level low` without waiver.
- The app uses Next's strict TypeScript convention (`dom`, `dom.iterable`, `esnext`, `skipLibCheck:true`), confirmed against [Next's configuration defaults](https://github.com/vercel/next.js/blob/canary/packages/next/src/lib/typescript/writeConfigurationDefaults.ts). `skipLibCheck` skips declaration-file checking, not application/test checking; the root strict configuration is unchanged. The initial dependency-declaration errors were fixed without weakening project source checks. [TypeScript's documented tradeoff](https://www.typescriptlang.org/tsconfig/skipLibCheck.html) remains explicit.
- Initial HTML and disclosure are server rendered. One client island owns ephemeral budget validation/reset, chip state, appearance selection and preview state. CSS system preference supplies initial light/dark appearance; no remote fonts, storage read, effect-driven hydration state, or client-only data authority. A guarded layout effect restores focus only after a user invokes a recovery action.
- The production server and browser test server bind `127.0.0.1` only. Next telemetry is disabled in validation/CI. Runtime footprint is a Node process plus static prerendered routes; no deployment is made by this task. The local SVG favicon and line icons are original, versioned assets.

## Design and interaction contract

`packages/design-system/src/tokens.ts` is the authority for warm-ivory/graphite/petrol light/dark semantic colors, platform-native typography, spacing, radius, focus, motion and responsive dimensions. Generated `aw-` CSS applies no shared global element reset; only the web app owns its page layout/reset. The app reuses Button/Field/Chip/Card/Skeleton/Banner rather than cloning them.

Controls have native roles, associated labels/hints/errors, selected/disabled/busy semantics, 44×44 CSS px minimum targets and visible focus. Decorative icons and skeletons are hidden from screen readers. Reduced motion disables skeleton/feedback animation and smooth scrolling. Error/retry/success/clear actions retain a useful keyboard focus. No status depends on color alone. Appearance and all example inputs reset on reload; they are not Saved or persistent preferences.

No application analytics event/collector is introduced: the task contract prohibits network fetches and has no product search/save behavior to instrument. Native example input/click/change handlers are covered by the E2E suite; later TASK-0103 owns the planned privacy-safe product analytics. Backend logs/metrics/traces, migrations and a risky production feature flag are not applicable to this isolated, non-deployed presentation foundation.
