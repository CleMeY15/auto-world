## Capability boundary

Use a new input-free manual workflow on reviewed protected `main`, guarded to its first run and first attempt. The publication job has only `contents: read` and `packages: write`; no OIDC, signing or attestation permission. [GitHub grants permissions to the whole job](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#how-permissions-are-calculated-for-a-workflow-job), so omitting `GITHUB_TOKEN` from early child environments does not create a step-level privilege boundary. The audited publisher process receives the Actions token, excludes it from every build/export child environment and context, and uses it only for `docker login` through stdin after local proof. This stage does **not** run the PostgreSQL diagnostic, the candidate, the scanner or any candidate helper. It may run the reviewed Dockerfile's bounded offline `RUN` to construct the image: pre-pull the exact public base by digest, use `docker build --network=none --pull=false`, fixed cgroup limits, pinned material bytes and no secret, SSH, token, Docker-auth directory or host socket passed to the build context.

No private image archive, layer, Docker configuration or scan report may cross jobs or be uploaded as an artifact in this public repository: [artifacts on public repositories can be read through GitHub's API](https://docs.github.com/en/rest/actions/artifacts#list-workflow-run-artifacts). The only public artifact is one bounded, redacted technical receipt. The private GHCR object is staging storage, not the required supported-lifetime second copy. That copy and a real restore remain admission gates.

3. Inspect the locally built candidate's config, platform, labels, base-layer DiffID prefix and new layers. Override inherited PostgreSQL VOLUME with the reviewed tmpfs profile, bind each export to its exact image config ID and compare complete before/after volume inventories. 4. Immediately before dispatch, use the existing local read-only GitHub credential to confirm package ID `15408021` is still Private with reviewed repository access; retain this separate preflight. The runner then authenticates the fixed harmless bootstrap manifest, proves isolated anonymous denial, and requires the authenticated raw manifest to be byte-identical. Check the unique `candidate-<run-id>-attempt-1` tag is absent; ambiguous registry responses fail. Recheck protected `main` immediately before a single `docker push`.
5. After the push, retrieve exact raw candidate manifests by tag and digest, require byte equality, expected config and bounded layer descriptors, and prove anonymous denial of the digest. Permit the OCI-to-Docker schema 2 media-type translation of the ten base layers only when each compressed digest and byte size remains identical; a changed blob or unrelated media type fails closed. The new layers still await independent authenticated retrieval and DiffID verification. Record a confirmed write as `PUBLISHED_UNADMITTED` immediately after the exact tag/digest proof even if the later anonymous-access or cleanup control fails; the job result still fails in that case. An attempted but unconfirmed write remains `ATTEMPTED_OUTCOME_UNCONFIRMED` and is never automatically retried.
6. Remove only images, tags, stopped containers and work paths with proven ownership. Remove owned references separately and compare complete before/after inventories; foreign or uncertain objects stay untouched and fail cleanup. Preserve the receipt and any confirmed or uncertain GHCR object. Disable the exhausted workflow after its one run, whatever the outcome.
