Publish one newly reconstructed PostgreSQL gosu-correction candidate to the already verified Private package `ghcr.io/clemey15/auto-world-postgres-gosu`, with maximum result `PUBLISHED_UNADMITTED`. This is ADR-0007 stage 2, not vulnerability admission or supported service startup. Their run budgets are exhausted and workflow `368603665` remains disabled.

## Capability boundary

Use a new input-free manual workflow on reviewed protected `main`, guarded to its first run and first attempt. The publication job has only `contents: read` and `packages: write`; no OIDC, signing or attestation permission. GitHub grants job permissions for the whole job, so merely omitting `GITHUB_TOKEN` from early step environments does not create a step-level privilege boundary. This stage therefore does **not** run the PostgreSQL diagnostic, the candidate, the scanner or any candidate helper. It may run the reviewed Dockerfile's bounded offline `RUN` to construct the image: pre-pull the exact public base by digest, use `docker build --network=none --pull=false`, fixed cgroup limits, pinned material bytes and no secret, SSH, token, Docker-auth directory or host socket passed to the build context. The job exposes the Actions token only to the final registry publisher process and passes it to `docker login` through stdin.

No private image archive, layer, Docker configuration or scan report may cross jobs or be uploaded as an artifact in this public repository. The only public artifact is one bounded, redacted technical receipt. The private GHCR object is staging storage, not the required supported-lifetime second copy. That copy and a real restore remain admission gates.

## Executable plan

2. Verify the runner's managed Docker/classic-builder identity, baseline complete image/container inventories, and absence of the owned tag, config and container names. Validate exact base manifest/config/platform and all committed APK, index, key, APKBUILD and provenance hashes. Build only the pinned Dockerfile with network disabled and bounded resources. Do not `docker run`, `start` or `exec` the candidate.
3. Inspect the locally built candidate's config, platform, labels, base-layer DiffID prefix and new layers. Save and parse its bounded Docker archive, then compare complete base and candidate root filesystems exported from never-started owned containers. Apply the strict gosu/APK filesystem delta policy; this structural proof is not a runtime or vulnerability audit. Never upload the archive or exports.
4. Before publication, confirm the same package ID `15408021` is still Private with reviewed repository access. Authenticate the fixed harmless bootstrap manifest, prove isolated anonymous denial, then require the authenticated raw manifest to be byte-identical. Check the unique `candidate-<run-id>-attempt-1` tag is absent; ambiguous registry responses fail. Recheck protected `main` immediately before a single `docker push`.
5. After the push, retrieve exact raw candidate manifests by tag and digest, require byte equality, expected config and bounded layer descriptors, and prove anonymous denial of the digest. Mark a confirmed write `PUBLISHED_UNADMITTED`; an attempted but unconfirmed write remains `ATTEMPTED_OUTCOME_UNCONFIRMED` and is never automatically retried. A later cleanup failure must not erase a confirmed remote write.
6. Remove only images, tags, stopped containers and work paths with proven ownership. Remove owned references separately and compare complete before/after inventories; foreign or uncertain objects stay untouched and fail cleanup. Preserve the receipt and any confirmed or uncertain GHCR object. Disable the exhausted workflow after its one run, whatever the outcome.
