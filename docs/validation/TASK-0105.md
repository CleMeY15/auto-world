## Run, observe, stop and rollback

Use Node 22.23.2 and pnpm 10.15.0, Docker/Compose and the functional stack's pinned images. On Linux, the existing OpenSearch `vm.max_map_count` prerequisite applies. From the dedicated worktree:

```sh
pnpm install --frozen-lockfile
pnpm prototype:search:test
```

This is the task's executable isolated composition: it creates only its own disposable two-service project, provisions separate search worker/API roles, applies the connector/search migrations, injects the search read port into the existing API, runs the scenarios and removes only its owned test resources. It does not replace the user's demo server or bind its preview port. A persistent combined application launch/recovery flow belongs to TASK-0106.

For composition code, the explicit conditional export `@auto-world/search/prototype` exposes `createSearchPrototype`; ordinary/default and production imports are rejected. Its `consume()` processes one bounded batch (`published`, `idle`, `busy`, `waiting`, `halted`); callers must respect persisted backoff and must not auto-replay a halt. `reconcile()` verifies and rebuilds only confirmed missing/corrupt generations, never treats transport failure as proof of corruption. `health()` exposes queue count/lag and warning/critical state; the optional telemetry sink receives only fixed event names and bounded durations/counts. Existing API metrics/logs/spans are reused unchanged.

For a halt, retain the immutable quarantine, identify and correct the cause, then record a distinct operator decision with `reviewReplay("review_reference")` before consumption resumes. This records the decision and starts a new bounded retry cycle without erasing the previous quarantine. It is never invoked automatically by the consumer. Do not edit canonical records, reset attempts or delete quarantine to recover. The integration's owner-level fault injection/restoration is confined to disposable test data and is not an operator repair procedure.

Stop scheduling new work, abort the current owned operation and close the API plus `runtime.close()` before rolling back application code. The old offline demo remains usable without this conditional composition. Preserve the PostgreSQL schema/history and diagnostic records; schema `down` is intentionally empty-only and refuses populated consumer state. Migration bytes are checksummed; a later schema change requires a new migration, not editing an applied migration. The task's runner performs ownership-checked cleanup in `finally`, including failure/cancellation; if cleanup cannot be confirmed it records failure rather than claiming success.

Obsolete derivative indices are eligible after 120 seconds from replacement (or abandoned attempt creation); the current publication and younger generations are retained for in-flight readers. Cleanup uses exact durable names and exact mapping ownership, never a wildcard delete. Failed cleanup emits `cleanup_deferred`; investigate persistent failures instead of removing the ownership guard. Payload cleanup affects only obsolete sanitized snapshots; canonical records, delivered keys, attempts and quarantine/review evidence remain immutable.
