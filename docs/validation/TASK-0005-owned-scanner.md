Canonical source hashes and the private module file must remain exact. The private checksum file may contain only bounded, classified additions; it never becomes an input to tests or builds.

Selected sums must agree across module-list and download records. Historical module-file additions require a corresponding graph node and a fresh SumDB lookup line. A/B preparation compares semantic sums, classified additions, the graph, relevant SumDB contents and complete material closure before tests. Raw checksum-file hashes remain measured separately: physical line order is not mistaken for a Go version-ordering guarantee. `Origin` remains an observation per construction, outside the equality predicate.

Preparation records identities after each command and checks file/directory limits before parsing. Each private preparation is capped at 64 MiB and its peak is accounted before allocation. Unused derived JSON copies are removed. The native [`go list -json=Module` projection](https://pkg.go.dev/cmd/go#hdr-List_packages_or_modules) retains exhaustive dependency enumeration while limiting output to the module fields actually consumed. Existing source locks, patch bytes, compiler pins, security thresholds, offline tests/builds and cleanup ownership remain unchanged.
