## Contract and failure review

| Scenario | Required planned behavior and owner |
| --- | --- |
| Valid fixture | TASK-0101 stages exact raw bytes/SHA before decode and retains an unresolved Listing with observed price/mileage provenance; TASK-0102 projects only sanitized public evidence. |
| Malformed fixture | SDK bounded parse failure; no canonical publication or result. |
| Contradictory observation | Both observations remain immutable; deterministic display selection and accessible history show the conflict. |
| Withdrawal | Active search excludes the listing; detail/Saved can explain unavailable status without deleting evidence. |
| Revoked/expired test authority or partial full run | SDK refuses further publication or preserves checkpoint/reconciliation semantics; fixture policy is never real legal authority. |
| Partial/stale projection | `DemoSearchResponseV1` carries committed `dataAsOf` and explicit state/reason; API/UI do not claim a complete count or silently use current wall time as freshness. |
| Poison outbox event | TASK-0105 bounds retries, quarantines immutably, stops checkpoint advance and requires operator-reviewed replay; index lag alert behavior is tested. |
| API failure/offline/denied local storage | UI retains search context, offers retry, and keeps removable Saved IDs without false offline detail or save-success claims. |
| Rollback/recovery | Demo entrypoint can be disabled; local Saved schema supports recovery. Supported tasks separately require migration/replay, raw-inclusive backup, isolated restore and index rebuild at a recorded watermark. |

The accepted vehicle schema contains listing-scoped observations only at this boundary; no `VehicleEntity` identity, make/model/year/photo/VIN, valuation or seller action is fabricated. Internal raw/source/run identifiers remain outside the public DTO. Production import exclusion and external-network denial are implementation gates in TASK-0101/0102, not claims proven by this document.
