# Deterministic streaming USTAR writer

This preparation increment adds a bounded raw archive writer tested with authored
synthetic files. It does not consume a Seaweed binary, base layer or real notice,
and it adds no image builder, downloader, workflow or publication capability.

## Contract

`writeUstarArchive({ entries, sink, openContent, signal })` copies and validates the
complete ordered inventory before writing or opening content. Entries retain
their supplied order. Identical metadata, order and content produce identical
bytes and DiffID regardless of input chunk boundaries. Ordering the eventual
filesystem is the caller's explicit responsibility; sorted inventory comparison
is separate from serialization order.

Only canonical ASCII file, directory and symlink entries are accepted. Paths,
link targets, exact fields, duplicates, whiteouts and explicit non-directory
ancestors are checked before streaming. Missing directory entries are permitted
by this generic writer; the existing final filesystem validator requires the
complete expected inventory. Numeric metadata must fit canonical USTAR octal
fields. Long paths use a deterministic split at the rightmost slash that fits
the 155-byte prefix and 100-byte name fields. Links must fit 100 bytes. There is
no PAX, GNU, hardlink, device, xattr or capability encoding.

The raw stream uses 512-byte USTAR headers, empty owner names, authoritative
numeric UID/GID, zero device fields, zero file padding and exactly two zero end
blocks. Special permission bits and supplied integer mtimes remain exact.
The existing reader's limits apply: 2 GiB total raw bytes, 100,000 members and
1 MiB input chunks. File contents are hashed incrementally.

`openContent` is synchronous and must immediately return a conforming Node
Readable in byte mode. Each opened file must end at its declared size and
SHA-256 before the writer advances to another member. Node's pipeline provides
backpressure; its abort signal also reaches the active content stream. Opened
streams are destroyed and awaited on failure, and later files remain unopened.
An arbitrary asynchronous opener is deliberately outside this contract because
its pending promise cannot in general be cancelled or safely reclaimed.

The `SEAWEED_USTAR_WRITE_RECEIPT_V1` result has authority `PREPARATION_ONLY` and
state `COMPLETE` only after pipeline completion. It records raw size, expected
size, DiffID and member metadata/offsets. Errors reject without a complete
receipt and report `INCOMPLETE` with `generatedBytes`; that count describes
generated bytes, not persisted or durable bytes. The library owns no host path
and makes no file immutability, no-follow, atomic-write or durability claim.

A future output runner must exclusively create an owned partial file, close it,
re-read and independently validate the entire archive and intended inventory,
then promote it. A write receipt alone cannot authorize Docker import or image
admission. A future source adapter must separately authenticate the successful
native run and its retained materials.

## Validation and integration

Synthetic tests cover exact headers and round-trip metadata through the existing
reader, long paths and numeric boundaries, deterministic output, preflight
rejection before I/O, malformed openers, short/extra/changed content, source and
sink errors, cancellation and slow-sink backpressure. Pinned local/fresh checks,
independent reviews and final-head/main CI are recorded in the focused PR.

A separate local compatibility probe writes five authored entries with Node
22.23.2 and reads them with Python3.12.14's standard `tarfile` parser. It verifies
the complete ordered metadata, special directory permissions, UID/GID, mtime,
long notice-shaped path, symlink target, offsets and file hashes without host
extraction. The 4,608-byte archive has DiffID
`sha256:aa261b828b57e134c5c79ef3efe5d31d4f09fcbf974ab7321cff6b1cfad18757`.
Its raw size, DiffID and exact two end blocks are checked independently too.
This is synthetic format compatibility, not native Docker or real-image proof.

## Primary reference

[Node22.23.2 streams](https://nodejs.org/download/release/v22.23.2/docs/api/stream.html)
defines async-generator pipeline backpressure, abort propagation,
`addAbortSignal`, `finished` and async-iterator stream destruction. The content
opener contract requires streams that complete their lifecycle when destroyed;
it does not promise cancellation of a hostile custom implementation.
