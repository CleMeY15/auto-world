## Filesystem and controller limits

This is an in-situ snapshot under a trusted host/kernel/private-lease actor and quiescent writers, without a claim of OS immutability or durable supported retention. O_NOFOLLOW protects the final component only; Node's path-based API and repeated parent/file guards do not establish atomic whole-path confinement against a malicious same-UID or privileged host. O_NONBLOCK is a liveness measure; an O_RDWR FIFO can open on Linux and must still fail the regular-file check before any read. Synchronous fsync/close calls are guarded but not preemptible; successful flushes do not prove crash/power-loss durability across devices/filesystems. See the versioned Node and Linux references in the plan.

A separately reviewed native controller must supply bounded process supervision, exclusive source ownership/quiescence, daemon stop, revalidation of both hashes/snapshots and explicit preservation of the output namespace. It must produce its own authenticated preservation receipt before cleanup or publication. This source snapshot does not authorize a controlled archive read, image load, registry write or service startup. A later Docker save/load/inspect/tag/push/readback chain may establish the first new registry manifest digest without rebuilding; it cannot borrow an old subject's digest or infer it from a configuration ID.
