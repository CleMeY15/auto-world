## Boundary and prerequisites

[PR45](https://github.com/CleMeY15/auto-world/pull/45) merged the closed structural scanner at `19dc8b6bd22139a9bb08f2297a06ceb20fa22c7a`. Its [final-head CI](https://github.com/CleMeY15/auto-world/actions/runs/35914022515) and [protected-main CI](https://github.com/CleMeY15/auto-world/actions/runs/35914403902) passed 315 Linux root tests with zero skips and every quality gate. The one-time [native structural diagnostic](https://github.com/CleMeY15/auto-world/actions/runs/35914604994), first run and first attempt, independently scanned both 4,854-entry build ZIPs and the three single-entry JSON ZIPs, refreshed GitHub origin and removed all five temporary ZIPs. Its receipt remains `ZIP_STRUCTURAL_ONLY`, `PREPARATION_ONLY`, `materialValidation: NOT_RUN`, `extraction: NOT_RUN` and `candidateAuthorization: NOT_AUTHORIZED`. Its serialized receipt supplies no authority to this stage.

This increment must obtain a new authenticated source view and download the same five fixed GitHub artifacts internally. The caller supplies only a private empty owned Linux parent, an optional abort signal and an aggregate deadline. It cannot select a repository, run, artifact, ZIP profile, sink, comparator, URL or expected digest. All five owned ZIPs are rescanned by the bounded reader while each accepted entry is written exclusively to a private partial tree. Keep the raw ZIPs, two extracted build trees and three exact JSON receipts in one closure; do not expose a partial tree as complete.

The transaction must validate both full build trees with `validateArtifactDirectory`, check each native gate's exact schema/state/result/buildResult/repeat/totalBytes, run `compareBuilds` over the actual two trees with fixed source identity, and compare `comparisonReceiptBytes` byte-for-byte with the downloaded native comparison receipt. Before atomic same-filesystem promotion, recheck fresh authenticated origin and every owned filesystem identity. Abort, timeout, corrupt bytes, missing material, mismatched receipt, source drift, unexpected entry, substitution or uncertain cleanup must return no success receipt and never authorize a candidate. Cleanup deletes only identities created and still owned by this transaction; unknown replacements are left for inspection and reported as failure. As in the bounded ZIP reader, the private parent is workflow-owned and assumes no concurrent same-UID or privileged writer; filesystem checks fail closed on observed substitution but are not a defense against a process with equal OS authority.

A success result is `PREPARATION_ONLY` with `candidateAuthorization: NOT_AUTHORIZED`. It proves this materialization transaction at the tested instant, not durable authority from a serialized JSON or extracted path. A later image builder must consume the closure inside an equally authenticated transaction or revalidate it. No Docker image, registry object, package permission, scanner report or four-service runtime is created here.

## Validation and operation

Synthetic adversarial tests must cover exact-five success, CRC/digest/layout failures, abort/deadline, exclusive file creation, symlink/hardlink/root or leaf replacement, fsync/close/cleanup failure, invalid build/gate/comparison semantics, byte-different native receipt and atomic-promotion collision. The manual read-only Linux workflow must reject non-main, repeated run or repeated attempt before storage creation, use no artifact upload, and clean the materialized tree through its retained in-process ownership evidence. The one-time live replay must finish before the source artifacts expire on 7 October 2026. The aggregate deadline and abort apply to network transfer and ZIP streaming; the existing synchronous build validator and comparator cannot be interrupted mid-call, so the code checks the budget before and after each call and the Actions job timeout is the hard outer limit. A killed runner cannot promise in-process cleanup or emit a success receipt. Quality CI alone cannot prove consumption of the real source artifacts.
