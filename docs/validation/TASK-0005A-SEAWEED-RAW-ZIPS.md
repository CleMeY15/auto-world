# TASK-0005A — Authenticated raw source ZIP download

Status: focused Linux-only preparation under validation. No ZIP content has been admitted, extracted or used to construct an image.

## Boundary

[PR43](https://github.com/CleMeY15/auto-world/pull/43) merged the live GitHub source-origin gate after independent review and final-head/protected-main CI. This increment consumes that gate internally and downloads the exact five ZIP artifacts from the reviewed run by fixed artifact ID. The caller supplies only an empty, absolute, user-owned `0700` directory, an optional abort signal and an aggregate deadline. It cannot choose a repository, URL, artifact, digest, executable or subprocess.

The Linux runner opens and retains the directory descriptor, creates five fixed-name direct children with `O_CREAT|O_EXCL|O_NOFOLLOW|O_RDWR` and mode `0600`, and accesses them through `/proc/self/fd/<directory-fd>/`. Each `gh api` child uses GET against `github.com` and the pinned REST version, has no shell or writable stdin, and must finish before the next artifact starts. The transfer rejects an early end, extra byte, bad SHA-256, nonzero exit, abort or timeout. It then syncs and rehashes the saved file through the retained descriptor, checking that the owned regular file and directory identities still match their names. A second complete persisted-byte reread precedes the fresh independent GitHub origin check, which rejects deletion, rerun, expiry or changed metadata during the download. The deadline and abort signal apply during every reread; the final origin is required again immediately before success. A failure returns no receipt and removes only created files whose inode identities still match; it never recursively clears a caller directory or deletes an unknown replacement. If a path changes or cleanup cannot prove absence, the operation reports `seaweed_raw_zip_cleanup_failed` and leaves the uncertain path for manual inspection.

The result is explicitly `RAW_ZIPS_ONLY`, `PREPARATION_ONLY`, `zipValidation: NOT_RUN`, `extraction: NOT_RUN` and `candidateAuthorization: NOT_AUTHORIZED`. Its JSON fields do not carry the private GitHub-origin mark. The following materialization stage must revalidate the owned files, scan all five ZIP structures and contents, check the two build trees and three receipts, and only then consider an atomic promotion. The returned paths are not durable authority against a later writer. The trusted workflow-owned parent and same-UID/privileged-writer assumption match the bounded ZIP reader's filesystem contract.
