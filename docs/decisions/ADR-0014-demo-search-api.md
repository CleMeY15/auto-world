# ADR-0014 — Loopback synthetic search API V1

Status: Proposed for TASK-0102; independent architecture/API/security review required. Depends on accepted TASK-0101/ADR-0013 through PR148 and matching main CI38179981070. No supported infrastructure or real-source authority follows.

## Decision and implementation plan

Use the roadmap-selected Fastify/TypeScript stack, one exact dependency version after official maintenance/license/security verification. API core in services/api/src consumes only the public DemoReadPort declaration and frozen public parsers. The separate services/api/demo factory composes connectors/synthetic's demo-condition harness over the existing SDK test-support store; it is excluded from the production build/export graph and refuses NODE_ENV=production. No ingestion service import, replacement store, database, external asset/network, generic router or AI parser.

HTTP routes are POST /v1/demo/search with the exact DemoSearchQueryV1 JSON body, and GET /v1/demo/listings/:listingId with no query parameters. Successful responses wrap the unchanged DemoSearchResponseV1 as {schemaVersion:1,requestId,data}. A known missing detail maps to bounded not_found; unsupported/invalid queries are editable invalid_query, never inferred. Typed failures use {schemaVersion:1,requestId,error:{code}} with a closed vocabulary and no caller values, stack, source text or exception messages. Read outcome failures map to invalid_cursor, read_unavailable or cancelled. Protocol failures use bounded invalid_request, method_not_allowed, unsupported_content_type and request_too_large codes.

Request IDs are req_ plus32 lowercase hexadecimal characters. A valid single x-request-id is propagated; invalid/duplicate IDs reject. Generated IDs are random opaque correlations. The same ID and abort signal reach the read port and error response. Only fixed known routes enter logs/labels; unknown paths are never recorded as text.

The demo process binds 127.0.0.1 only. Host/Origin values are exact allowlists, DNS rebinding/forwarded-header substitutions reject, CORS denies by default. JSON search input is bounded to8KiB and unknown query strings/methods/content types reject. Local loopback tests are the only network exception. No credentials or external URL configuration exists. Read-returned DTOs are revalidated and detached before publication; malformed outcomes and thrown internal messages become read_unavailable.

The demo read adapter reads exactly ADR-0013's manifest scope from SDK committed projections and immutable observations. It selects latest price/mileage by observed UTC time then ordinal observation ID; contradictory/withdrawn history is retained. Search includes active only, detail may show ended evidence. It never constructs VehicleEntity or exposes VIN/raw/source/run/snapshot/policy identities. Watermarks require real committed SDK page/finalization evidence within this synthetic model; unavailable reads cannot become empty complete results. complete/partial/stale and60s boundary follow ADR-0013 unchanged.

Cursors are opaque cur_ plus64 lowercase hex. Bind fixture version, committed projection watermark, normalized filter/sort and position to a bounded per-adapter continuation map; never encode internal IDs. Changed query, replaced projection, unknown cursor and invalid page position reject. Fixed20-item pages; exact nextCursor iff another matching result remains; complete totalCount is global fixture-scoped count. Limits above10000matches/256evidence entries reject, with no silent truncation. Tests prove first/middle/last pages over SDK-committed synthetic test data, not only declaration validation.

Telemetry uses a bounded injected sink: api_requests_total{route,status}, api_errors_total{code}, api_request_duration_ms, structured request-ID/route/status/duration/code logs and api.search/read_port.query spans. Only the correlation ID and allowlisted event/count/field names appear; no request body/filter/cursor/VIN/source/raw/persistent-user data. Test-only bounded failure alerts are explicit; no deployed collector or pager claim.

## Verification, delivery and rollback

Read-port behavioral tests cover history association, ordering/filter ties, withdrawal, missing detail, replay, partial/stale/freshness and cursor invalidation. HTTP contract/injection tests cover ingress/egress redaction, cancellation/request IDs, protocol denial, telemetry, malformed read outcomes and failure alerts. Production import/build and blocked-egress child tests cover the isolated composition; they do not claim an OS sandbox. Measure fixture p95 under500ms with exact environment/sample count; no production-scale result. Run real nonzero Turbo lint/type/test/build gates, root tests, existing browser regression, secrets/dependency audit and independent API/security/operations review. Exact final-head CI, identical merge tree and protected-main CI govern dependency acceptance. UI wiring remains TASK-0103.

Rollback disables/removes only the demo entrypoint and API increment, preserving canonical SDK evidence and public V1 history. No server data migration, image admission, credential, namespace or task effect.
