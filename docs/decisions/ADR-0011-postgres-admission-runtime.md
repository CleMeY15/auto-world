## Authority and private state

The only supported entrypoint is `admitted-postgres.mjs`, calling `runPostgresSupportedSession({kind: "POSTGRES_SUPPORTED_SESSION_V1", intent})` with a closed intent enum SERVICE, SQL_CHECK, MIGRATION, BACKUP, RESTORE_VERIFY. No caller supplies an authority object, dependency, URL, repository, ref, image, path, Docker argument, SQL, environment override, skip or callback. The broker owns every phase and remains in the foreground until the complete session ends. Historical diagnostics keep their separate NOT_AUTHORIZED scope.

`openPostgresAdmissionAuthority()` accepts no arguments. It captures exactly one bounded nonempty GH_TOKEN or GITHUB_TOKEN from the foreground environment, rejects duplicate/conflicting variables, and removes both names from the ambient environment. Credentials remain private to the authority session for renewal; they never enter argv, events, results, files or child environments. Root-owned fixed paths supply local state, never caller configuration. Production exposes no test factory or injected authorization/transport seam.

One bootstrap resolves authenticated protected `main`, loads admission-policy.json, admission-inventory.json and package-controls.json at that exact forty-hex commit through the fixed GitHub Contents endpoint, verifies path/type/base64/Git-blob identity and bounded bytes, then rechecks identical protected main. Redirects, head movement, protection loss, malformed data, authentication/rate/network failure or timeout deny. Do not infer review from the protected boolean: repository delivery independently requires review, exact-head CI, identical merge tree and main CI. Policy fixes api.github.com, ghcr.io and API version2026-03-10, 5-second requests, 1MiB/item, 8MiB aggregate and 30-second initial bootstrap; renewal has20seconds.

Only a chain-valid authenticated terminal revocation exposes the closed error code postgres_admission_authority_revoked, allowing truthful revocation telemetry. Other malformed, unauthenticated, uncertain or PENDING input remains the generic postgres_admission_authority_denied; raw authority bodies and credentials never enter diagnostics.

Registry access follows the [official Distribution authentication protocol](https://distribution.github.io/distribution/spec/auth/): validate the fixed GHCR challenge, exchange credentials only at its fixed token endpoint for the exact repository pull scope, and use that private registry token for manifests. A GitHub API token is not assumed to be a registry bearer token. [GitHub's registry documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry) establishes the supported foreground credential type. Unsupported CI issuer identity fails closed until its reviewed authentication contract exists; CI compilation alone does not establish runtime access.

Policy and inventory have closed schemas and canonical revision preimages. An immutable generation root binds exact subject/manifest/config/ordered DiffIDs, build and source identities, accepted P1, runtime/SQL, P4 and P5, public acceptance file hashes, private locator identity, execution-code byte pins and exactly the two existing waivers. PENDING revisions have null dates. The first ACTIVE revision sets dates once; later ACTIVE/REVOKED revisions preserve them byte-for-byte. Current-evidence refresh changes only P2/P3 references and freshness metadata. A changed frozen root starts a greater PENDING generation.

The reviewed-main consumer classification is non-authoritative metadata enforced by exhaustive source/workflow tests. It is not imported by a supported runtime or offline observer, grants no authority and is excluded from execution-file pins, alongside mutable package-control evidence and the self-referencing inventory. Adding a diagnostic-only producer can update that classification without changing the frozen runtime. Any new code imported or called by the supported broker, authority or offline observer belongs to the immutable closure and requires a new generation.

Every revision excludes mainSha and its own hash from its preimage. Recompute canonical SHA256, require aligned enclosing hashes and contiguous previousRevisionSha256 links, and require the current number/hash to equal the last entry. Root-owned high-water state at `/opt/auto-world/postgres-admission/high-water.json` binds generation/revision/computed hash/state/resolved main. Accept only an identical retained prefix and contiguous successors. Missing high-water with existing owned runtime state, rollback, shortening or divergence denies. A chain-valid authenticated REVOKED successor persists terminal high-water before denial/drain even if current evidence is stale. Unauthenticated, invalid or mutated input never updates it; an older ACTIVE revision cannot revive a revoked generation.

Before the first high-water publication, create and durably seal the fixed root-owned authority-state-initialized.json sentinel. Keep it permanently. Missing high-water with this sentinel or a retained generation-N/restore-generation-N runtime directory denies before any mutation. Preparing only the private locator and offline health does not mark a virgin host initialized. Uncertain sentinel publication also denies; deleting a revoked high-water cannot make its earlier ACTIVE revision eligible again.

Every revision preimage also binds generationRootSha256, the SHA256 of the canonical compact-JSON-plus-LF frozen root; it must equal the computed root hash. This makes the retained revision prefix authenticate frozen fields without embedding a current main SHA or self-hash. High-water publication is durably atomic: create a fixed exclusive update-intent marker in the held root-owned parent and fsync it and its parent before mutation; exclusively create the canonical temporary record, fsync and verify complete readback/EOF/native identity; verify the old target, rename the owned temporary record, fsync the parent and reopen/verify the exact new record. Only then retire the owned intent marker and fsync the parent. An existing marker or any persistence uncertainty denies/drains and leaves the host unusable until an explicit reviewed repair; it cannot restore an older ACTIVE state after a crash.

## Four private archive roots and daily observation

The exact ordered archive roles are evidenceCopy, evidenceRetrieve, controlCopy, controlRetrieve: two synchronized COPY/RETRIEVE pairs. Omitting the control pair does not satisfy P5. Reviewed main publishes no local path, execution nonce, inode, UID or payload. It binds only the fixed locator schema and exact bytes/SHA256. Derive `/opt/auto-world/postgres-admission/generation-<admissionGeneration>.json` solely from the validated positive generation number. Fixed protected root-owned ancestors, NOFOLLOW anchors, root:root0400/nlink1, bounded1MiB held read, physical EOF, full digest-before-parse, canonical LF JSON, exact keys, native reseal and certain closure authenticate the private locator. Its paths/native tuples must match the accepted P5 ACK/journal and public proof hashes; missing or substituted material denies. Preserve the actual accepted control modes: original P1 policy and launch plan0400, staged P5 policy and ACK/control/terminal/post-ACK journal0600. Do not change or reseal historical controls to fit an assumed mode.

FAST verification on every lease authenticates the locator and small P1/P5 controls, all four roots/objects/reservations, exact object membership/counts/bytes, root/object profiles, empty reservations and disjoint native identities. It reads no object payload and cannot extend a FULL observation. FULL verification additionally reads every object in bounded1MiB chunks, proves size/physical EOF/SHA256/native stability and attempts every descriptor closure. It interprets no payload and never writes, repairs, deletes, reseals, opens a network/Docker socket or spawns a child.

The immutable reviewed-main archive bindings and executable byte pins are distinct from a mutable local FULL observation. A daily observation does not require a main commit or ACTIVE revision. The separate root-owned observation retainer invokes the pinned offline verifier, observes bounded canonical output plus actual exit/signal/both EOFs, validates generation/locator/code/policy binding, and atomically retains a root:root0600/nlink1 envelope at the fixed generation-specific health path using exclusive temporary creation, file/parent fsync and rename. It grants no runtime capability. Authority independently reseals and validates the envelope, ordered nonfuture timestamps, maximum24-hour age and exact immutable bindings. FAST never replaces this envelope.

Health publication also creates and fsyncs a fixed exclusive generation update-intent marker before the temporary record. Authority rejects either that marker or an unfinished temporary record before and after health verification. The retainer retires the owned marker only after target durability, full readback/reseal and descriptor closure; publication/closure uncertainty preserves or reinstates quarantine. A published VERIFIED body alone cannot be consumed while its update remains uncertain.

At actual activation an immutable root-owned offline maintenance input records the frozen generation, locator, command/policy pins and actual dates, without a self-hash or main-SHA cycle. The offline verifier and retainer continue after REVOKED or support expiry through archiveUntil; stale P2/P3 do not suppress preservation. Install the local Task Scheduler owner AutoWorld-Postgres-ArchiveHealth only at reviewed activation, at startup and daily03:15UTC with missed-run execution and retained failure history. No task, workflow, automation or heartbeat is created by the initial PENDING implementation. No archive is automatically deleted.

Install each generation's exact execution-file closure in a separate immutable root-owned recipe directory. A later generation cannot overwrite an earlier generation's verifier, policy or maintenance input. The retained Windows-to-WSL action must continue invoking the matching offline recipe through that generation's archiveUntil; changing the current supported runtime does not remove prior preservation commands.

The activation-pinned Windows action invokes the root-owned Linux verifier/retainer through the existing Ubuntu-24.04 WSL distribution and fixed pinned Linux executable paths. Retain the executable/action/distribution details privately. Activation must prove that this Windows-to-WSL action sees the same ext4 archive roots and native identities, and captures the retainer's actual exit/EOF result. Windows/DrvFS permissions never substitute for the Linux root/NOFOLLOW guarantees. The initial implementation documents and tests this bridge without installing or enabling the scheduler.

## Lease, composite operation and child isolation

Authority session methods are acquire(), renew(priorLease), assertCurrent(lease, phase, minimumRemainingMs), close(). Leases are identity-authenticated private WeakMap records, single-session/generation/revision/main bound and noncloneable. assertCurrent returns only a frozen public binding with the generation root, image identities, issue/deadline monotonic times, archive-set digest and five strict UTC currentness timestamps: p2ValidUntil, p3SettingsValidUntil, p3ManifestValidUntil, archiveValidUntil and supportValidUntil. A copied acknowledgement cannot authorize an effect.

The lease lasts at most60seconds monotonic and is shortened to the earliest of its five currentness deadlines, rechecked after bootstrap I/O and high-water persistence. Equality with a deadline is expired; each effect reserves its five-second operation window. Full serialized renewal starts by35seconds, renewal budget20seconds plus5seconds drain buffer. A1-second watcher and every bounded await/I/O chunk enforce the deadline; wall-clock changes cannot extend it. Full renewal repeats bootstrap, chain/high-water/currentness and archive checks even on unchanged main. P2 uses the existing validUntil and48-hour vulnerability-DB policy; Java identity/time remains recorded without a max-age rejection. Authenticated package Settings UI evidence remains required within24hours, live API authority NOT_ESTABLISHED. Ordered authenticated/anonymous-denied/authenticated identical exact-manifest checks remain current for15minutes. FULL archive health lasts at most24hours. PENDING, expiry, revocation, substitution or ambiguous currentness denies before effects.

A current P2 scanner archive is a per-run packaging of the same immutable image. Its reviewed materializer derives a run/revision alias, so Docker-save RepoTags can change its TAR hash without changing the manifest, config or ordered DiffIDs. Authenticate the exact root-pinned candidate-remote policy bytes, validate that policy and the complete nested materialization receipt with the existing production validators, and explicitly bind nested run/revision to the outer receipt and current audit source. Require the fixed scanner artifact name, matching alias and archive SHA/size, and identical registry subject, manifest/config/ordered DiffIDs and publisher identities. A hash-format check alone is insufficient. This does not relax the separately retained runtime archive identity: supported Docker load still uses its exact305474048-byte `2c1b6b002076fa3772aa9fc899befb86fe525aee1ee1c8007d85bba200c73a05` copy.

Native Trivy CreatedAt uses UTC RFC3339Nano, including an actual eight-digit fractional timestamp in the retained report. Preserve that original timestamp literally in the current projection and raw-report equality. Only audit.checkedAt accepts UTC-Z seconds with zero through nine fractional digits, validated through the existing production calendar parser. validUntil, Settings, health, support and lease timestamps retain their strict canonical formats; all existing nonfuture/currentness rules remain. Do not rewrite scanner bytes or normalize the projection away from the raw report. This correction changes an authority execution pin, so it starts generation2 PENDING with a new revision1/null dates and preserves generation1's PENDING root/revision summary. Its new exclusive locator may reference the same accepted immutable controls and four archive roots, with no archive recopy; a fresh generation-bound FULL/FAST observation is required. No support activation follows from the compatibility correction.

Only private broker phases acquire/load the image, own the daemon/socket, create/start containers and volumes, run fixed SQL/migration/backup/restore, stop and clean up. Image, volume, container and operation capabilities bind the authentic lease, main, generation, daemon/socket and owned resource identities; an operation is consumed once before one spawn and expires within5seconds. Revalidate process/config/socket/native/label identities before and after effects; serialize operations. No IPC, detached broker, generic execute callback or low-level public route exists. SERVICE remains foreground for renewal and owned-container lifetime.

The daemon remains fresh per session, while PostgreSQL data lives in a generation-owned bind directory under the fixed admission root. Its enclosing directory is root:root0700 and held through NOFOLLOW anchors. Root-owned data binding records the frozen generation/image, directory dev/inode and actual PostgreSQL UID/GID obtained from the verified image identity operation; do not guess an account number. Subsequent sessions reattach only the same protected directory and accepted ownership profile. Never delete or chown existing data. Restore verification uses a separate owned target and cannot overwrite the original data directory. Changes of generation cannot silently reuse another generation's data; migration/reattachment is an explicit reviewed P7 operation.

Reuse the existing pure Docker identity/configuration guards and default daemon helper, never its diagnostic lease authority. Load only the locally retained exact archive into the isolated daemon, inspect the exact config/image ID and ordered DiffIDs, and execute by exact image ID. No tag resolution/fallback or caller digest is allowed. Any later CI registry acquisition stays in the foreground process and yields a fully verified credential-free archive before docker load.

Children receive explicit minimal PATH/LANG/LC_ALL/TZ/HOME and an owned empty Docker configuration, fixed argv and closed stdio/descriptors. No GitHub/GHCR/ACTIONS/proxy/cookie/Authorization credentials, authority bodies or ambient Docker routing are inherited. A random PostgreSQL bootstrap secret uses a private owned file, separate from authority credentials. SQL values/files are data in fixed reviewed templates. MIGRATION must use the reviewed foundation's fixed apply/idempotence/rollback/reapply contract; no arbitrary caller script or SQL is accepted. BACKUP/RESTORE_VERIFY preserve source backups and target only proven-owned volumes.

Authority failure cancels active work, denies new effects and initiates bounded drain. Stop owned containers gracefully within30seconds; only cleanup capabilities survive authority loss. Preserve every data volume, backup, archive, source history and failed proof. Remove only proven-owned stopped containers and temporary clients/imported image state when safe. Uncertain ownership or shutdown yields CLEANUP_UNCERTAIN, never false success. Never silently retry cancelled SQL/migration/backup/restore.

## Calendar, observability and validation

Actual reviewed activation establishes strict UTC YYYY-MM-DD supportStartedAt; the activation change must merge on that UTC date or be updated/re-reviewed. supportEndsAt is the one-calendar-year anniversary, clamping February29 to February28. Support is half-open at UTC midnight. archiveUntil is exactly365elapsed UTC days after supportEndsAt. Historical proofs keep null dates; revocation preserves established dates and archives.

Events have fixed enums, bounded public hashes and finite durations; metric labels have fixed result/reason/state/intent/phase values. Emit authority, lease/renewal, session/phase, drain and currentness gauges/alerts. Token, environment, SQL, path, private receipt and raw child output are forbidden. Sink failure cannot authorize/renew or suppress drain. Alerts initially use bounded structured events and the owning process/CI exit status; no paging backend is claimed.

Tests exercise the actual supported modules through a tests-only VM/builtin harness with simulated network/filesystem/children, not an exported production authority seam. Prove denial before every effect, canonical history/rollback/terminal revocation, leap/calendar boundaries, source/socket/resource substitution, full renewal/deadline cancellation, foreground lifetime, credential isolation, archive corruption/closure and no-write maintenance, all fixed intent graphs and classification of every diagnostic/consumer. Then complete targeted native checks where applicable, lint/typecheck/tests/build/secrets/audit and distinct architecture/security review. Final activation/P7 separately require actual fresh eligibility/access/archive, exact final-head CI, identical reviewed merge/main CI and operational evidence.
